# Release Note Template

Template source: Confluence page `3117121666`, version `1`.

## Version Number - Feature Title

Fill every field. Use `N/A` only when the reviewed evidence confirms the field does not apply.

| Field | What to write | Required |
|---|---|---|
| Jira Epic | Link or key for the originating epic | Yes |
| Title | Five words or fewer; name the feature, not the ticket | Yes |
| Code Release | Major.minor release value | Yes |
| Type | Feature or Enhancement | Yes |
| Strategic Theme | Copy from the Jira epic | Yes |
| Initiative | Copy from the Jira epic | Yes |
| Business Problem | What was broken or missing before this change | Yes |
| Summary of Change | What changed for users or administrators | Yes |
| User Impact | Who is affected and how | Yes |
| Configuration Impact | New or changed configuration, or `N/A` | Yes |
| Known Limitations | Known issues, exceptions, or `N/A` | Yes |
| Testing Evidence | Test cases, QA notes, or explicit gap | Yes |
| Related Documentation | Linked functionality/config/API docs, or `N/A` | Yes |

## Evidence Reviewed

List the epic, child issues, test evidence, PRISM/OneShot evidence, PR references, and attachments reviewed.

## Gaps / Not Found

List missing evidence explicitly. Do not hide missing release fields.
